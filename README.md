# Raj Devnath

Building **[semlayer](https://github.com/semlayer-dev/semlayer)** — the semantic layer that infers itself.

Point it at a warehouse. It profiles every column, discovers the foreign keys
nobody declared, decodes the status codes, and finds the business rules hiding
in your aggregate tables — then writes the whole thing down as a portable
semantic layer, with **confidence, provenance and lifecycle on every claim**,
ready for any agent to read over MCP.

Hand-authoring that model takes a quarter of someone's life. It shouldn't.

**[Try it in your browser →](https://try.semlayer.dev)**  · nothing to install

### What I'm working on

- **[semlayer](https://github.com/semlayer-dev/semlayer)** — the engine and CLI.
  Fair Source (FSL-1.1-ALv2); the format and its JSON Schemas are Apache-2.0,
  permanently, because interoperability is the point.
- **[action-demo](https://github.com/semlayer-dev/action-demo)** — SQL checked
  against the layer, posted as findings on a pull request.
- **[dbeval](https://github.com/raj-devnath/dbeval)** — a neutral head-to-head
  benchmark for data-agent context.

### What I'd like to hear about

If you maintain routing rules by hand — which aggregate answers which query,
which table is the one to use, which columns are dead — I want to hear how you
do it today. That's the problem I'm trying to make disappear.
